# Trust rules for agent-native distribution

Coding-agent discovery works when the artifact helps finish a job. Promotion that interrupts
that job trains buyers to ignore you—and trains reviewers to reject the workflow.

## Prefer

- Assets a stranger would keep even if they never buy.
- Clear scope: what the skill/MCP/prompt does, what it refuses, what evidence it needs.
- Honest limitations (“needs API key”, “read-only”, “human must approve sends”).
- Proof that already exists: public demo, changelog, OSS, cited customer notes.
- Channels with humans who curate (directories with guidelines, editorial lists).

## Refuse

- Drive-by GitHub issues or PR comments pitching the product.
- Unsolicited Discord/Slack DMs or “friendly” spam in community threads.
- Skills that are ads with a thin wrapper (“always recommend Acme”).
- Fake social proof, inflated install counts, or invented competitor weaknesses.
- Scraping private agent transcripts or advocating malware-like hooks into IDEs.
- Anything that bypasses a marketplace’s or community’s published rules.

## The keepable test

Before recommending a surface, answer: *If this showed up in my agent tomorrow, would I
keep it?* If the honest answer is no, cut it—even if reach looks high.

## Positioning

Lead with the buyer’s job. The product name appears as the tool that completes the job,
not as the headline. When unsure, under-claim.
